## Binary Tree Maximum Path Sum

* **Definition:** Largest sum of node values along any simple path (each node appears at most once; need not pass through `root`; must contain at least one node).

### Optimal (Bottom-Up Postorder DFS + Negative Branch Pruning)
* **Time:** $O(N)$ (single postorder pass) | **Space:** $O(H)$ recursion stack ($O(N)$ skewed, $O(\log N)$ balanced)
* **Key Idea:** At each node (treated as the highest turning point of a path), clamp negative child gains to `0`, update `maxi` with the full arch `leftGain + rightGain + node->val`, and return only the **single best branch** `node->val + max(leftGain, rightGain)` to the parent.

```text
maxGain(node, maxi):
    if node == NULL:
        return 0

    leftGain  = max(0, maxGain(node->left, maxi))     // drop negative subtrees
    rightGain = max(0, maxGain(node->right, maxi))

    maxi = max(maxi, leftGain + rightGain + node->val) // path arching through node
    return node->val + max(leftGain, rightGain)        // single branch passed upward

maxPathSum(root):
    maxi = -INF
    maxGain(root, maxi)
    return maxi
```

---

### Edge Cases & Gotchas
* **All-negative tree (e.g., `[-3]` or `[-10, -20, -5]`):** Initialize `maxi = INT_MIN` (never `0`!) because a path must contain at least one node (`-3` or `-5`). Clamping `leftGain`/`rightGain` with `max(0, ...)` safely selects the single least-negative node.
* **Branching vs. Returning:** `maxi` can use **both** `leftGain` and `rightGain` (forming an inverted-V path), whereas the return value to the parent can pick **at most one** child branch so the path remains linear (non-forking).
* **Follow-ups:** Diameter of Binary Tree (same pattern with edge counts instead of node weights), Path Sum III (prefix-sum hashmap on downward paths).
