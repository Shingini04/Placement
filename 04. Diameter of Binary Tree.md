## Diameter of Binary Tree

* **Definition:** Number of **edges** on the longest path between any two nodes in the tree (need not pass through `root`).

### 1. Brute Force (Top-Down)
* **Time:** $O(N^2)$ (recomputes subtree height at every node) | **Space:** $O(H)$
* **Key Idea:** At every node, compute `height(left) + height(right)` and take the max across `root`, `left`, and `right`.

---

### 2. Optimal (Bottom-Up Postorder DFS)
* **Time:** $O(N)$ (single postorder pass) | **Space:** $O(H)$ recursion stack ($O(N)$ skewed, $O(\log N)$ balanced)
* **Key Idea:** Treat every node as a potential **curving point** (highest node on the path). Update `diameter = max(diameter, lh + rh)` on the way up while returning `1 + max(lh, rh)` to the parent.

```text
height(node, diameter):
    if node == NULL:
        return 0

    lh = height(node->left, diameter)
    rh = height(node->right, diameter)

    diameter = max(diameter, lh + rh)   // edges through current curving point
    return 1 + max(lh, rh)              // height passed upward

diameterOfBinaryTree(root):
    diameter = 0
    height(root, diameter)
    return diameter
```

---

### Edge Cases & Gotchas
* **Edges vs. Nodes:** Diameter counts **edges** (`lh + rh`), not nodes (`lh + rh + 1`). Single-node tree returns `0`.
* **Path doesn't pass through root:** Handled automatically since `diameter` is updated at every internal node, not just `root`.
* **Follow-ups:** Binary Tree Maximum Path Sum (replace `1 + max(lh, rh)` with `node->val + max(0, max(lh, rh))`), Tree Diameter in general graphs (2-BFS / 2-DFS from arbitrary node).
